1. Overview — What This Tool Does

The K3s Cluster Configuration Generator is a browser-based tool that produces all the configuration files needed to deploy a highly available K3s Kubernetes cluster on baremetal servers.

You fill in a form with your network details, node IPs, MAC addresses, and preferences. The tool generates 26 configuration files bundled as a ZIP archive. These files cover:

  • Network configuration — DHCP static leases, DNS entries, /etc/hosts, router checklist
  • OS disk layout — AutoYaST (XML) and Ignition (JSON) disk partitioning for each node
  • SSH hardening — authorized keys, sshd hardening config
  • Kernel tuning — sysctl parameters for K3s and container networking
  • HAProxy — load balancer configuration for the K3s API server
  • Keepalived — Virtual IP failover configuration per master node
  • K3s — server and agent config.yaml for each node
  • Storage — Longhorn Helm values or local-path StorageClass
  • variables.yaml — all your settings in one file (for re-generation later)

2. Prerequisites

Hardware Requirements

RoleCountCPURAMDisk
Master node3 (required)2+ cores4 GB+40 GB+ (SSD recommended)
Worker node1+ (recommended 3)2+ cores4 GB+40 GB+ (SSD recommended)

Network Requirements

  • All nodes on the same Layer 2 network (for VRRP/Keepalived)
  • DHCP server with static lease support (DHCPv4 required, DHCPv6 optional)
  • Internet access on all nodes (for package installation and K3s download)
  • A deployment host (laptop/workstation) with SSH access to all nodes

Information You Need Before Starting

  • IP addresses for each node (IPv4 required, IPv6 optional)
  • MAC addresses for each server's network interface
  • A free IP address for the Virtual IP (VIP)
  • Your network gateway and DNS server addresses
  • Your SSH public key(s)
  • Your target disk device names (e.g., /dev/sda, /dev/nvme0n1)
Tip: If you don't know MAC addresses yet, install the OS first using DHCP, then retrieve them with ip link show eth0 | grep ether and re-generate the configuration.

3. Phase 1 — Generate Configuration Files

1

Open the Configuration Generator

Navigate to the Configuration Generator in your browser. The form is organized into colored sections, each configuring a different aspect of your cluster.

2

Fill in the Operating System Section

Select openSUSE MicroOS (community, free) or SUSE Linux Enterprise Micro (commercial, requires registration code).

3

Configure SSH Keys

Enter your GitHub username(s) to auto-fetch public keys, and/or paste additional public keys directly. Enable "Disable Password Authentication" for production.

4

Configure Network Settings

Set your network interface name (e.g., eth0, ens3), cluster domain, DNS server, gateway, and subnet masks. Choose your IPv6 mode:

  • Disabled — IPv4 only (simplest)
  • DHCPv6 — static IPv6 leases via DUID (recommended for servers)
  • SLAAC — auto-configured from router advertisements
  • Both — DHCPv6 + SLAAC combined
5

Set the Virtual IP (VIP)

Enter an unused IP address on your subnet for the floating Virtual IP. This IP will be managed by Keepalived and used as the K3s API endpoint. Workers and kubectl connect through this address.

6

Configure Master Nodes

Fill in hostname, IPv4, IPv6 (if enabled), and MAC address for each of the 3 master nodes. If using DHCPv6, click "Generate" next to each DUID field (or use "Generate All DUIDs").

Expand Advanced: Per-Node Hardware if individual nodes have different network interfaces or disk devices.

7

Configure Worker Nodes

Add worker nodes with the "+ Add Worker Node" button. Fill in the same details as master nodes. You can add or remove workers at any time.

8

Configure K3s Settings

Set the K3s version (leave empty for latest), cluster token (leave empty to auto-generate), and CIDRs for pod and service networks. The defaults work well for most deployments.

9

Choose Disk Layout

  • Single Root — one Btrfs partition, simplest setup
  • Multi-Partition (recommended) — separate partitions for OS, K3s data, and storage on a single disk
  • Multi-Disk — dedicated disks for OS, K3s data, and storage (best I/O isolation)
10

Choose Persistent Storage

  • Longhorn — distributed replicated storage (production recommended)
  • Local-Path — simple node-local storage (dev/lab)
  • None — no persistent storage provisioner
11

Configure HAProxy, Keepalived, and DHCP

The defaults are suitable for most setups. Change the HAProxy stats password from the default admin in production environments.

12

Generate and Preview

Click "Generate Configuration". The tool validates all fields (errors are highlighted in red with messages). Once valid, the generated files appear below in preview tabs. Review them to ensure correctness.

5. Understanding the Generated Files (All 26 Files)

Here is what each generated file does and where it needs to be deployed:

Network Configuration (network/)

FilePurposeWhere to Apply
dhcpd4-leases.conf ISC DHCPv4 static leases (MAC → IPv4 for all nodes) Include in your DHCP server's /etc/dhcp/dhcpd.conf
dhcpd6-leases.conf ISC DHCPv6 static leases (DUID → IPv6 for all nodes) Include in your DHCP server's /etc/dhcp/dhcpd6.conf
dnsmasq-leases.conf dnsmasq DHCP leases + DNS records (alternative to ISC DHCP) Include in dnsmasq config or /etc/dnsmasq.d/
hosts /etc/hosts entries for all nodes (IPv4 + IPv6) Append to /etc/hosts on every node
router-checklist.md Human-readable checklist of all router/firewall configuration needed Reference document — follow the checklist on your router

OS Configuration (os/)

FilePurposeWhere to Apply
sysctl-k3s.conf Kernel parameters (IPv4/IPv6 forwarding, bridge-nf, inotify, conntrack) Copy to /etc/sysctl.d/90-k3s.conf on every node, run sysctl --system
ssh-authorized-keys SSH public keys for all nodes Copy to /root/.ssh/authorized_keys on every node
sshd-hardening.conf SSH daemon hardening (disable passwords, pubkey only, max retries) Copy to /etc/ssh/sshd_config.d/90-hardening.conf on every node
{hostname}/disk-partitioning.xml AutoYaST disk partitioning profile (per node) Use during SLE Micro automated installation
{hostname}/disk-ignition.json Ignition first-boot disk config (per node) Use during openSUSE MicroOS automated installation via USB

HAProxy (haproxy/)

FilePurposeWhere to Apply
haproxy.cfg TCP load balancer for K3s API (port 6443), with stats page Copy to /etc/haproxy/haproxy.cfg on all 3 master nodes

Keepalived (keepalived/)

FilePurposeWhere to Apply
master-01/keepalived.conf VRRP config for master-01 (MASTER, priority 101) Copy to /etc/keepalived/keepalived.conf on master-01
master-02/keepalived.conf VRRP config for master-02 (BACKUP, priority 100) Copy to /etc/keepalived/keepalived.conf on master-02
master-03/keepalived.conf VRRP config for master-03 (BACKUP, priority 99) Copy to /etc/keepalived/keepalived.conf on master-03

K3s Configuration (k3s/)

FilePurposeWhere to Apply
master-01/config.yaml First server config (cluster-init: true, bootstraps etcd) Copy to /etc/rancher/k3s/config.yaml on master-01
master-02/config.yaml Joining server config (server: https://master-01:6443) Copy to /etc/rancher/k3s/config.yaml on master-02
master-03/config.yaml Joining server config (server: https://master-01:6443) Copy to /etc/rancher/k3s/config.yaml on master-03
worker-01/config.yaml Agent config (server: https://VIP:6443) Copy to /etc/rancher/k3s/config.yaml on worker-01

Storage (storage/)

FilePurposeWhere to Apply
longhorn-values.yaml Helm values for Longhorn (replica count, data path, UI toggle) Used with helm install for Longhorn deployment

Variables (variables.yaml)

FilePurposeWhere to Apply
variables.yaml All your cluster settings in one YAML file Keep for reference, or use with python3 generate.py --vars variables.yaml to re-generate configs locally

6. Phase 3 — Network Preparation (Router/DHCP)

Before installing the OS, configure your network infrastructure so that nodes will receive the correct IP addresses at boot.

1

Open the Router Checklist

Review generated/network/router-checklist.md — it contains a complete list of everything to configure on your router/firewall with your actual cluster values.

2

Configure DHCPv4 Static Leases

Use the generated lease file that matches your DHCP server:

  • ISC DHCP (dhcpd) — include generated/network/dhcpd4-leases.conf in your /etc/dhcp/dhcpd.conf
  • dnsmasq — include generated/network/dnsmasq-leases.conf in your dnsmasq configuration
  • Router admin UI — manually create static leases using the MAC → IP mappings from the generated files
# Example: ISC DHCP server
sudo cp generated/network/dhcpd4-leases.conf /etc/dhcp/conf.d/k3s-leases.conf
echo 'include "/etc/dhcp/conf.d/k3s-leases.conf";' | sudo tee -a /etc/dhcp/dhcpd.conf
sudo systemctl restart dhcpd
3

Configure DHCPv6 Static Leases (if using IPv6 with DHCPv6 mode)

# Example: ISC DHCPv6 server
sudo cp generated/network/dhcpd6-leases.conf /etc/dhcp/conf.d/k3s-leases6.conf
echo 'include "/etc/dhcp/conf.d/k3s-leases6.conf";' | sudo tee -a /etc/dhcp/dhcpd6.conf
sudo systemctl restart dhcpd6
4

Configure DNS Records

Create A (and AAAA if using IPv6) records for all nodes and the VIP hostname. The generated/network/hosts file contains all the mappings you need.

5

Reserve the VIP

The Virtual IP must not be assigned to any physical device. Exclude it from your DHCP dynamic range, or create a dummy reservation to prevent assignment.

6

Configure Firewall Rules

Open the following ports on your network firewall (if one exists between nodes):

PortProtocolPurposeWhere
6443TCPK3s API ServerMasters
2379-2380TCPetcd client + peerMasters
10250TCPKubelet metricsAll nodes
8472UDPFlannel VXLANAll nodes
30000-32767TCP/UDPNodePort ServicesWorkers
Protocol 112VRRPKeepalived failoverMasters

7. Phase 4 — Install openSUSE MicroOS

Why openSUSE MicroOS? It is an immutable, container-optimized OS with automatic transactional updates. It provides a minimal, secure base ideal for Kubernetes nodes. No license or subscription required.

Option A: Interactive Installation (Recommended for First Time)

1

Download the ISO

Download from get.opensuse.org/microos

  • Select Bare Metal / Virtual Machine → Offline Image (full installer)
  • Architecture: x86_64

Write the ISO to a USB drive:

# Linux/macOS
sudo dd if=openSUSE-MicroOS-DVD-x86_64-*.iso of=/dev/sdX bs=4M status=progress

# Or use balenaEtcher, Rufus (Windows), or Ventoy
2

Boot and Install

  1. Boot the server from the USB drive
  2. Select "Installation" from the GRUB boot menu
  3. Wait for the installer to load
  4. Configure the following:
    • System Role: Select "MicroOS" (not "MicroOS Desktop")
    • Disk: Select your target disk (e.g., /dev/sda). Use the default Btrfs layout for now — the generated disk partitioning config can be applied during automated re-installation later.
    • Network: Leave as DHCP (your static DHCP leases handle addressing)
    • Time: Set your timezone, enable NTP
    • Root Password: Set a temporary root password
    • SSH: Ensure SSH service is enabled
  5. Confirm and begin installation
  6. Reboot when complete, remove USB drive
3

Repeat for All Nodes

Install openSUSE MicroOS on all 3 master nodes and all worker nodes. Each node should boot and get its expected IP address from the DHCP static lease.

4

Verify SSH Access

# From your deployment host, test SSH to each node:
ssh root@192.168.1.101 "hostnamectl"   # master-01
ssh root@192.168.1.102 "hostnamectl"   # master-02
ssh root@192.168.1.103 "hostnamectl"   # master-03
ssh root@192.168.1.111 "hostnamectl"   # worker-01

Option B: Automated Installation with Ignition (Advanced)

For automated, unattended installation using the generated Ignition configs:

1

Prepare a USB Drive with Ignition Config

# Format a USB drive with the label "ignition"
sudo mkfs.ext4 -L ignition /dev/sdX1

# Mount and copy the node-specific Ignition config
sudo mount /dev/sdX1 /mnt
sudo cp generated/os/master-01/disk-ignition.json /mnt/config.ign
sudo umount /mnt

The Ignition config handles disk partitioning, SSH keys, hostname, and first-boot services automatically.

2

Boot with Both USB Drives

Insert both the MicroOS installation ISO USB and the Ignition config USB. Boot from the ISO — MicroOS will detect the Ignition config on the labeled USB and apply it during first boot.

3

Repeat for Each Node

Use the corresponding generated/os/{hostname}/disk-ignition.json file for each node. Each file contains the correct hostname and disk layout for that specific node.

SLE Micro alternative: If using SUSE Linux Enterprise Micro instead, use the AutoYaST profiles (generated/os/{hostname}/disk-partitioning.xml) with the boot parameter autoyast=http://<server>/disk-partitioning.xml. See the full OS installation guide for details.

8. Phase 5 — OS Configuration

After the OS is installed on all nodes, apply the generated OS configuration files.

Option A: Automated (Recommended)

1

Run the OS Configuration Script

# From the repository root (where generated/ was extracted)
./scripts/01-configure-os.sh

This script automatically deploys:

  • generated/os/sysctl-k3s.conf → /etc/sysctl.d/90-k3s.conf on all nodes
  • generated/network/hosts → appended to /etc/hosts on all nodes
  • generated/os/ssh-authorized-keys → /root/.ssh/authorized_keys on all nodes
  • generated/os/sshd-hardening.conf → /etc/ssh/sshd_config.d/ on all nodes
  • Installs required packages, loads kernel modules, configures firewall

Option B: Manual Deployment

Deploy the generated files manually to each node via SCP:

1

Set Hostnames

# On each node, set the hostname:
ssh root@192.168.1.101 "hostnamectl set-hostname master-01.k3s.local"
ssh root@192.168.1.102 "hostnamectl set-hostname master-02.k3s.local"
ssh root@192.168.1.103 "hostnamectl set-hostname master-03.k3s.local"
ssh root@192.168.1.111 "hostnamectl set-hostname worker-01.k3s.local"
2

Deploy /etc/hosts

# Copy to all nodes:
for node in 192.168.1.101 192.168.1.102 192.168.1.103 192.168.1.111; do
    scp generated/network/hosts root@${node}:/tmp/k3s-hosts
    ssh root@${node} "cat /tmp/k3s-hosts >> /etc/hosts"
done
3

Deploy Kernel Parameters (sysctl)

for node in 192.168.1.101 192.168.1.102 192.168.1.103 192.168.1.111; do
    scp generated/os/sysctl-k3s.conf root@${node}:/etc/sysctl.d/90-k3s.conf
    ssh root@${node} "sysctl --system"
done
4

Deploy SSH Keys and Hardening

for node in 192.168.1.101 192.168.1.102 192.168.1.103 192.168.1.111; do
    scp generated/os/ssh-authorized-keys root@${node}:/root/.ssh/authorized_keys
    ssh root@${node} "chmod 600 /root/.ssh/authorized_keys"
    scp generated/os/sshd-hardening.conf root@${node}:/etc/ssh/sshd_config.d/90-hardening.conf
    ssh root@${node} "systemctl restart sshd"
done
5

Load Kernel Modules and Install Required Packages

for node in 192.168.1.101 192.168.1.102 192.168.1.103 192.168.1.111; do
    ssh root@${node} <<'REMOTE'
# Load kernel modules
for mod in br_netfilter overlay ip_vs ip_vs_rr ip_vs_wrr ip_vs_sh nf_conntrack; do
    modprobe $mod
done
cat > /etc/modules-load.d/k3s.conf <<'EOF'
br_netfilter
overlay
ip_vs
ip_vs_rr
ip_vs_wrr
ip_vs_sh
nf_conntrack
EOF

# Install required packages (on MicroOS, uses transactional-update)
transactional-update pkg install open-iscsi nfs-client cryptsetup apparmor-parser
REMOTE
done

# IMPORTANT: Reboot all nodes to apply transactional updates
for node in 192.168.1.101 192.168.1.102 192.168.1.103 192.168.1.111; do
    ssh root@${node} "transactional-update reboot"
done
6

Configure Firewall on Each Node

# On master nodes (repeat for each master):
ssh root@192.168.1.101 <<'REMOTE'
firewall-cmd --permanent --add-port=6443/tcp
firewall-cmd --permanent --add-port=2379/tcp
firewall-cmd --permanent --add-port=2380/tcp
firewall-cmd --permanent --add-port=10250/tcp
firewall-cmd --permanent --add-port=8472/udp
firewall-cmd --permanent --add-port=8404/tcp
firewall-cmd --permanent --add-rich-rule='rule protocol value="vrrp" accept'
firewall-cmd --reload
REMOTE

# On worker nodes (repeat for each worker):
ssh root@192.168.1.111 <<'REMOTE'
firewall-cmd --permanent --add-port=10250/tcp
firewall-cmd --permanent --add-port=8472/udp
firewall-cmd --permanent --add-port=30000-32767/tcp
firewall-cmd --permanent --add-port=30000-32767/udp
firewall-cmd --reload
REMOTE
7

Verify OS Configuration

# On each node, verify:
ssh root@192.168.1.101 <<'REMOTE'
echo "=== Hostname ==="
hostnamectl | grep hostname
echo "=== Kernel Forwarding ==="
sysctl net.ipv4.ip_forward
sysctl net.ipv6.conf.all.forwarding
echo "=== Modules ==="
lsmod | grep br_netfilter
lsmod | grep overlay
echo "=== Connectivity ==="
ping -c1 master-02 && echo "OK" || echo "FAIL"
REMOTE

9. Phase 6 — Deploy HAProxy & Keepalived

HAProxy load-balances the K3s API across all masters. Keepalived manages the Virtual IP that floats between them.

Option A: Automated

./scripts/02-install-haproxy.sh

The script deploys generated/haproxy/haproxy.cfg and each node's generated/keepalived/{hostname}/keepalived.conf automatically.

Option B: Manual

1

Install Packages on All Masters

for master in 192.168.1.101 192.168.1.102 192.168.1.103; do
    ssh root@${master} "transactional-update pkg install haproxy keepalived"
done

# Reboot to apply
for master in 192.168.1.101 192.168.1.102 192.168.1.103; do
    ssh root@${master} "transactional-update reboot"
done
2

Deploy HAProxy Configuration (Same File to All Masters)

for master in 192.168.1.101 192.168.1.102 192.168.1.103; do
    scp generated/haproxy/haproxy.cfg root@${master}:/etc/haproxy/haproxy.cfg
done
3

Deploy Per-Node Keepalived Configuration

# Each master gets its OWN keepalived.conf (different priority)
scp generated/keepalived/master-01/keepalived.conf root@192.168.1.101:/etc/keepalived/keepalived.conf
scp generated/keepalived/master-02/keepalived.conf root@192.168.1.102:/etc/keepalived/keepalived.conf
scp generated/keepalived/master-03/keepalived.conf root@192.168.1.103:/etc/keepalived/keepalived.conf
Important: Each master node has a unique Keepalived config with different state and priority values. Do not copy the same file to all nodes.
4

Enable Non-Local IP Binding & Start Services

for master in 192.168.1.101 192.168.1.102 192.168.1.103; do
    ssh root@${master} <<'REMOTE'
# Allow HAProxy to bind to the VIP before Keepalived assigns it
echo "net.ipv4.ip_nonlocal_bind = 1" > /etc/sysctl.d/90-haproxy.conf
echo "net.ipv6.ip_nonlocal_bind = 1" >> /etc/sysctl.d/90-haproxy.conf
sysctl --system

# Start services
systemctl enable --now haproxy
systemctl enable --now keepalived
REMOTE
done
5

Verify HAProxy and VIP

# Check HAProxy is listening
ssh root@192.168.1.101 "ss -tlnp | grep 6443"

# Check the VIP is assigned (should be on master-01)
ssh root@192.168.1.101 "ip addr show | grep 192.168.1.100"

# Access HAProxy stats
curl http://192.168.1.101:8404/stats

10. Phase 7 — Bootstrap K3s Cluster

Option A: Automated

# Step 1: Bootstrap the first server
./scripts/03-install-k3s-first.sh

1

Deploy K3s Config to First Master and Install

# Create the K3s config directory on master-01
ssh root@192.168.1.101 "mkdir -p /etc/rancher/k3s"

Join master-03

Verify the Full Control Plane

# Check all masters are Ready

11. Phase 8 — Add Worker Nodes

Option A: Automated

./scripts/05-install-k3s-agents.sh

Option B: Manual

1

Deploy Agent Config and Install

# For each worker node:
ssh root@192.168.1.111 "mkdir -p /etc/rancher/k3s"

14. Troubleshooting

SymptomPossible CauseResolution
Node doesn't get expected IP DHCP static lease not configured or MAC mismatch Verify MAC with ip link show; check DHCP server logs; ensure lease is active
SSH connection refused SSH not enabled, firewall blocking, or wrong IP Enable SSH in installer; check firewall-cmd --list-ports; verify IP with ip addr
IPv6 addresses lost after sysctl Missing accept_ra = 2 in sysctl Verify sysctl net.ipv6.conf.all.accept_ra shows 2; re-deploy sysctl-k3s.conf
VIP not assigned to any node Keepalived not running or VRRP blocked Check systemctl status keepalived; ensure VRRP (protocol 112) is allowed through firewall
K3s node won't join cluster Wrong token, can't reach master-01, or firewall Verify token matches; test curl -k https://master-01:6443; check ports 6443, 2379-2380
kubectl shows node NotReady K3s agent can't reach API or CNI issues Check journalctl -u k3s-agent -f; verify VIP is reachable; check Flannel VXLAN (port 8472)
PVC stuck in Pending No StorageClass or Longhorn not ready Check kubectl get storageclass; verify Longhorn pods: kubectl -n longhorn-system get pods
transactional-update changes not applied MicroOS requires reboot to apply changes Run transactional-update reboot after package installs
